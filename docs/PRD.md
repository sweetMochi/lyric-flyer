# Lyric Flyer 產品需求文件

類似 YouTube Music 歌詞功能的個人歌詞播放器。使用者貼上 YouTube 網址建立歌曲，匯入對好時間的歌詞後，播放時歌詞逐行同步捲動，點擊歌詞可跳轉播放。日文歌曲可顯示振假名與羅馬拼音，非中文歌曲可顯示翻譯。歌曲以類似 Chrome 書籤管理員的方式整理

用語以 [GLOSSARY.md](../GLOSSARY.md) 為準，重大決策記錄於 [docs/adr/](./adr/)

## 目標與非目標

### 目標

- 單人使用、可安裝的 PWA，手機與桌機皆可使用
- 不需帳號、後端或 API Key（[ADR 0001](./adr/0001-pure-frontend-no-backend.md)、[ADR 0002](./adr/0002-iframe-api-and-oembed-only.md)）
- 歌詞資料由使用者以檔案形式保管，可隨時完整備份與還原

### 非目標

- 多人共用、帳號系統、雲端自動同步
- 站內搜尋 YouTube 影片、相關影片推薦
- 隱藏影片、只播放音訊
- 逐字（卡拉 OK 式）同步

## 階段範圍

### 第一階段

- 書籤管理員：資料夾樹、新增歌曲與資料夾、編輯（名稱與網址）、刪除、拖曳排序與移動、搜尋
- 播放頁：逐行同步、點擊跳轉、自動捲動、顯示開關、時間差微調、單曲循環、無法播放處理
- 匯入：歌詞檔（JSON）、LRC、歌曲庫檔（僅取代匯入），一次一個檔案
- 匯出：歌詞檔、歌曲庫檔
- 歌詞全由使用者在 APP 外手寫或轉換而來，振假名全由人工標註
- 儲存：localStorage

### 第二階段

- 打點編輯器：播放時按鍵標記每行開始時間，並可微調
- 振假名自動標注：在編輯器中以 lazy load 的 kuromoji 產生草稿，再由人工修正
- 播放序列（資料夾連續播放或獨立佇列）
- 常駐的迷你播放器，讓離開播放頁後仍可繼續播放（與播放序列一併規劃）
- 歌曲庫檔的合併匯入
- 單首匯入時以 videoId 比對的「覆蓋、新增、略過」三選一
- 歌曲的複製與貼上
- 從影片縮圖取主色作為播放頁背景

### 第三階段

- 儲存改為 IndexedDB（替換 `LibraryStore` 實作，見 [ADR 0006](./adr/0006-localstorage-behind-library-store.md)）
- i18n（屆時再規劃）

## 功能需求（第一階段）

### 路由與首頁

| 路由 | 畫面 |
| --- | --- |
| `#/` | 導向 `#/library/root` |
| `#/library/:folderId` | 書籤管理員，顯示該資料夾 |
| `#/play/:songId` | 播放頁 |

- 路由中的 id 不存在時，導回 `#/library/root` 並提示「找不到該資料夾或歌曲」
- 歌曲庫為空時，書籤管理員顯示「新增歌曲」與「匯入歌曲庫檔」兩個入口

### 新增歌曲與網址解析

可接受以下任一格式，抽出 11 碼 videoId，忽略 `t=`、`list=` 等其餘參數：

- `youtube.com/watch?v=`
- `youtu.be/`
- `music.youtube.com/watch?v=`
- `youtube.com/shorts/`
- `youtube.com/embed/`
- 直接輸入 11 碼 videoId

建立歌曲時呼叫一次 oEmbed，將影片標題存入歌曲節點的 `ytTitle`。歌曲名稱預設值依序取歌詞的 `title`、影片標題、videoId

oEmbed 失敗（離線、影片不存在、私人影片等）時不阻擋新增：`ytTitle` 可能為空值，歌曲名稱暫用 videoId，待下次成功播放時再補抓影片標題

同一支影片已存在於其他歌曲時不阻擋，但在對話框下方提示「此影片也存在於『資料夾路徑 / 歌曲名稱』」並附連結（[ADR 0005](./adr/0005-uuid-song-identity-and-duplicate-videos.md)）

### 書籤管理員

- 只有一個根資料夾，資料夾可無限層巢狀
- 根資料夾不可重新命名、刪除或拖曳
- 每首歌曲只屬於一個資料夾，不做標籤，也不做一首歌放在多個資料夾
- 工具列提供「新增歌曲」、「新增資料夾」、「匯入」、「匯出歌曲庫」
- 支援拖曳排序、拖曳移動到其他資料夾（Angular CDK `DragDrop` 與 `Tree`）
- 刪除資料夾時會遞迴刪除其中所有內容，確認對話框需顯示將刪除的歌曲數量。刪除歌曲時，其歌詞一併刪除
- 不做多選批次操作
- 搜尋範圍為所有歌曲的名稱、歌手與影片標題，結果每列在名稱下方顯示資料夾路徑，點擊後跳到該資料夾並高亮該歌曲

**版面**

- 桌機：左側為資料夾樹，右側列出目前資料夾內容
- 手機：單欄顯示目前資料夾內容，以麵包屑在資料夾之間導覽。長按項目啟動拖曳排序，移動到其他資料夾改由選單的「移動到…」選擇目標資料夾

**列表顯示**

- 歌曲列：縮圖（`mqdefault.jpg`，約 96×54，`loading="lazy"`）、歌曲名稱、歌手（來自歌詞，可能為空值）
- 歌曲狀態：只有「無法播放」會以「⚠ 無法播放」疊加在縮圖上，不顯示語言或「無歌詞」等其他標記
- 資料夾列：資料夾圖示與其中的歌曲數量

**歌曲選單**

- 編輯：開啟編輯對話框，包含「名稱」與「YouTube 網址」兩個欄位，修改網址即為替換影片
- 移動到…（手機版）
- 匯入歌詞：見「匯入與匯出」
- 匯出歌詞：沒有歌詞的歌曲停用此項
- 刪除

**資料夾選單**

- 重新命名
- 移動到…（手機版）
- 刪除

### 替換影片

入口有兩處，共用同一個編輯對話框：書籤管理員的「編輯」，以及播放頁無法播放時的「替換影片」按鈕

確認新網址後：

- 更新歌曲節點的 `videoId`
- 重新呼叫 oEmbed 更新 `ytTitle`
- 歌曲名稱與 `offsetMs` 保持不變，並提示「新影片的前奏長度可能不同，可在播放頁微調時間差」
- 新網址已被其他歌曲使用時，同樣只提示、不阻擋

### 播放頁

**版面**

YouTube 規範要求嵌入的播放器可見且不小於 200×200（[ADR 0002](./adr/0002-iframe-api-and-oembed-only.md)）

- 上方標題列：返回鍵（回到歌曲所在資料夾）、歌曲名稱、歌手
- 手機：影片固定於標題列下方（16:9 滿版寬），下方為可捲動的歌詞區，顯示開關位於歌詞區頂端工具列
- 桌機：影片在左、歌詞在右，兩欄並排
- 第一階段使用固定的深色主題
- 播放、暫停、進度等控制直接使用 YouTube 播放器內建的控制列，不另外自製
- 離開播放頁即停止播放

**同步與跳轉**

- 播放中以 `requestAnimationFrame` 節流為約每 100ms 呼叫一次 `getCurrentTime()`，計算目前行並寫入 signal，暫停時停止輪詢
- 歌詞行的實際開始時間為 `time + offsetMs`，結束於下一行開始時，最後一行持續到影片結束
- 實際開始時間小於 0 或超過影片長度時，限制在 0 至影片長度之間，顯示與跳轉皆套用
- 點擊任一歌詞行（含間奏行）時呼叫 `seekTo()` 跳到該行開始時間，若影片原本暫停則一併開始播放

**自動捲動**

- 播放時，目前行平滑捲動至畫面中央偏上
- 使用者手動捲動後暫停自動捲動，並浮出「回到目前歌詞」按鈕
- 點擊該按鈕，或 5 秒內沒有再操作，即恢復自動捲動

**時間差微調**

- 提供「歌詞提前 0.1 秒」與「歌詞延後 0.1 秒」按鈕，並顯示目前的時間差數值與「歸零」按鈕
- 調整結果寫回該歌曲的 `offsetMs`，匯出時一併帶出

**單曲循環**

開關預設關閉，狀態存於 `lf:settings`。關閉時影片播完即停在結尾，開啟時播完自動 `seekTo(0)` 重新播放

**播放器錯誤**

錯誤碼 100、101、150（無法播放）時：

- 播放區顯示「此影片無法播放」，提供「替換影片」按鈕與「在 YouTube 開啟」連結
- 不顯示歌詞
- 所有使用同一 videoId 的歌曲節點標記 `unavailable: true`，下次播放成功時一併清除

錯誤碼 2、5 時：顯示「播放發生錯誤，請重試」，不標記為無法播放

**沒有歌詞的歌曲**

只播放影片，歌詞區顯示「尚無歌詞，可匯入」

### 歌詞顯示

每一歌詞行依序垂直排列以下各層，目前行整組高亮：

1. 原文：振假名以原生 `<ruby><rt>` 呈現於漢字上方
2. 羅馬拼音：字級較小、顏色較淡
3. 翻譯：字級較小、顏色較淡

間奏行顯示「♪」

**顯示開關**

三個全域開關存於 `lf:settings`，所有歌曲共用，預設全部開啟：顯示振假名、顯示羅馬拼音、顯示翻譯。開關是否出現由歌曲語言與資料決定：

| 歌曲語言 | 振假名 | 羅馬拼音 | 翻譯 |
| --- | --- | --- | --- |
| 日文（`ja`） | 出現 | 出現 | 有翻譯語言時出現 |
| 中文（`zh-*`） | 不出現 | 不出現 | 不出現 |
| 其他（如 `en`） | 不出現 | 不出現 | 有翻譯語言時出現 |

**羅馬拼音來源**（[ADR 0004](./adr/0004-furigana-as-inline-markup-stored-in-file.md)）

- 歌詞行有 `ro` 時，以 `ro` 為準
- 否則以「假名原文加振假名讀音」經 wanakana 轉換
- 原文中的英文字母與數字（如「Lemon」、「1000」）原樣保留，全形標點轉為對應的半形標點
- 若該行有漢字未標振假名，無法轉換，該行不顯示羅馬拼音

### 匯入與匯出

一次只匯入一個檔案

**匯出**

- 單首：輸出 `{title}.song.json`（檔名不允許的字元會被替換），必定寫入 `id` 與 `videoId`
- 整庫：輸出 `lyric-flyer-library-YYYYMMDD.json`，內含書籤樹與所有歌詞

**單首匯入：工具列「匯入」（目標為目前資料夾）**

- 歌詞檔（JSON）：
  - `id` 命中既有歌曲時，詢問是否覆蓋，選否即略過
  - 沒有 `id` 或 `id` 未命中時，一律在目前資料夾新增歌曲，即使 videoId 已存在
- LRC：要求使用者貼上 YouTube 網址並選擇歌曲語言，再於目前資料夾新增歌曲

**單首匯入：歌曲選單「匯入歌詞」（目標為該歌曲）**

匯入的歌詞會覆蓋該歌曲原有的歌詞，歌曲的 id 維持不變

- LRC：直接使用該歌曲的 videoId，不需貼網址，只需選擇歌曲語言
- 歌詞檔（JSON）：檔案的 `videoId` 與歌曲不同時，警告「檔案綁定的是另一支影片」，確認後改用歌曲的 videoId

這也是第一階段更新「手寫且沒有 `id`」的歌詞的方式

**歌曲庫檔匯入**

第一階段只提供取代匯入：清空目前歌曲庫，完全換成檔案內容。執行前先提醒使用者匯出目前的歌曲庫檔作為備份

**驗證**

- 任何驗證錯誤都會拒絕整個檔案，並列出所有錯誤與其 JSON 路徑，例如「`lines[12].time` 格式錯誤」
- 警告不會擋下匯入，於匯入完成後列出，例如：
  - 「第 12 行有漢字未標振假名，該行無法顯示羅馬拼音」
  - 「中文歌曲不會顯示翻譯」（歌曲語言為 `zh-*` 卻有 `tr`）

## 資料格式

格式以 Zod v4 定義，並產生 JSON Schema 於 `public/schemas/`（[ADR 0003](./adr/0003-custom-json-with-zod-as-source-of-truth.md)）

### 歌詞檔 `*.song.json`（version 1）

```json
{
  "$schema": "./schemas/song.v1.schema.json",
  "format": "lyric-flyer/song",
  "version": 1,
  "id": "c3d4e5f6-…",
  "videoId": "SX_ViT4Ra7k",
  "title": "Lemon",
  "artist": "米津玄師",
  "lang": "ja",
  "translationLang": "zh-TW",
  "offsetMs": 0,
  "lines": [
    { "time": "00:00.00", "text": "" },
    {
      "time": "00:12.34",
      "text": "{夢|ゆめ}ならばどれほどよかったでしょう",
      "tr": "如果這一切都只是夢該有多好",
      "ro": "yume naraba dore hodo yokatta deshou"
    }
  ]
}
```

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `format` | 是 | 固定為 `lyric-flyer/song` |
| `version` | 是 | 格式版本，目前為 `1`，日後升版時於匯入時遷移 |
| `id` | 否 | 歌曲 UUID，手寫時可省略，匯出時必定寫入 |
| `videoId` | 是 | 11 碼 YouTube videoId，只用於匯出入，見下方說明 |
| `title` | 是 | 歌曲標題 |
| `artist` | 否 | 歌手 |
| `lang` | 是 | 歌曲語言，BCP 47 代碼，如 `ja`、`en`、`zh-TW` |
| `translationLang` | 條件 | 翻譯語言。任一行有 `tr` 時必填 |
| `offsetMs` | 否 | 時間差（毫秒），預設 `0`，正值代表歌詞延後（[ADR 0007](./adr/0007-offset-sign-opposite-to-lrc.md)） |
| `lines` | 是 | 歌詞行陣列，至少一行 |

videoId 以歌曲節點為唯一來源。本機儲存的歌詞不保存 `videoId`，只在匯出時由歌曲節點寫入檔案，匯入時依上述規則讀取

**歌詞行**

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `time` | 是 | 開始時間，格式為 `mm:ss.xx` 或 `mm:ss.xxx`。各行必須依時間遞增排列，否則視為驗證錯誤 |
| `text` | 是 | 原文，振假名以 `{漢字|かな}` 標記。空字串代表間奏行 |
| `tr` | 否 | 翻譯 |
| `ro` | 否 | 羅馬拼音，有值時覆寫自動轉換結果 |

**振假名標記規則**

- 語法為 `{原文|讀音}`，以詞為單位整組標註
- 熟字訓不拆字，例如 `{今日|きょう}`
- 特殊讀法照實標註，例如 `{宿命|さだめ}`
- 原文本身含有 `{`、`|`、`}` 時，以反斜線跳脫為 `\{`、`\|`、`\}`
- 大括號未成對、或缺少 `|` 時視為驗證錯誤

### 歌曲庫檔 `library.json`（version 1）

```json
{
  "format": "lyric-flyer/library",
  "version": 1,
  "exportedAt": "2026-10-29T08:00:00Z",
  "tree": {
    "id": "root", "type": "folder", "name": "", "children": [
      { "id": "a1b2…", "type": "folder", "name": "日文", "children": [
        {
          "id": "c3d4…", "type": "song", "videoId": "SX_ViT4Ra7k",
          "name": "Lemon", "ytTitle": "米津玄師 MV「Lemon」",
          "lyrics": {
            "title": "Lemon", "artist": "米津玄師", "lang": "ja",
            "translationLang": "zh-TW", "offsetMs": 0,
            "lines": [ … ]
          }
        }
      ]}
    ]
  }
}
```

- `tree` 為書籤樹，根節點 id 固定為 `root`，其餘節點 id 以 `crypto.randomUUID()` 產生
- 歌曲節點欄位：`id`、`type`、`videoId`、`name`，以及可能為空值的 `ytTitle`、`unavailable`、`lyrics`
- 歌詞直接嵌入所屬歌曲節點的 `lyrics` 欄位，結構為歌詞檔去掉 `$schema`、`format`、`version`、`id`、`videoId`，這些值改由歌曲庫檔與歌曲節點提供。沒有歌詞的歌曲省略 `lyrics`
- 歌曲庫檔只是匯出入格式，與本機儲存結構各自獨立：匯出時由 `LibraryService` 組成巢狀結構，匯入時再拆開存入 `LibraryStore`

**整體一致性**：節點 id 重複時視為驗證錯誤。嵌入的寫法讓「歌詞找不到所屬歌曲」與「歌詞和歌曲的 id、videoId 不一致」在結構上不可能發生，因此不需另外檢查

### LRC 匯入規則

- `[ti:]` 轉為 `title`。沒有 `[ti:]` 時改用影片標題
- `[ar:]` 轉為 `artist`
- `[offset:]` 反轉正負號後轉為 `offsetMs`
- 一行有多個時間戳（如 `[00:12.00][01:30.00]副歌`）時展開為多行
- 逐字時間標記 `<mm:ss.xx>` 直接移除
- 同一時間戳連續兩行時（常見的雙語 LRC 寫法），第二行視為 `tr`
- videoId 與歌曲語言由使用者在匯入時提供

### 本機儲存

所有讀寫都透過 `LibraryStore` 介面，第一、二階段實作於 localStorage（[ADR 0006](./adr/0006-localstorage-behind-library-store.md)）

| key | 內容 |
| --- | --- |
| `lf:meta` | `{ schemaVersion: 1 }`，啟動時檢查，必要時執行遷移 |
| `lf:tree` | 書籤樹 |
| `lf:lyrics:<songId>` | 單首歌詞（不含 `videoId`） |
| `lf:settings` | 顯示開關、單曲循環 |

- 啟動時呼叫 `navigator.storage.persist()`
- 寫入時捕捉 `QuotaExceededError`，提示使用者匯出歌曲庫檔

## 技術基準

- 使用最新版 Angular，以 Angular CLI 建立專案（SCSS、不使用 SSR）
- 採用 standalone components、Signals、zoneless change detection
- UI 使用 Angular CDK 加自訂樣式，不使用 Angular Material
- 套件管理使用 npm，程式碼品質使用 angular-eslint 加 Prettier
- 以 `@angular/pwa` 提供可安裝、離線可開啟的 App 外殼，離線時書籤管理員仍可瀏覽，播放則需連網
- PWA 有新版本時，顯示「有新版本，重新整理以更新」，由使用者決定是否重新整理
- 路由採 hash 模式（`withHashLocation()`），部署於 GitHub Pages
- 介面語系只有繁體中文

## 測試

以 Vitest 撰寫測試，只驗證對外行為，不測內部實作細節。UI 元件第一階段不寫測試

測試集中在兩個接縫：

- **歌詞載入管線**：輸入檔案文字（JSON 或 LRC），輸出「驗證過的歌詞或錯誤清單，加上警告清單」，以及可直接顯示的歌詞行模型（振假名片段、羅馬拼音、翻譯）。振假名解析、羅馬拼音轉換、LRC 轉換與各項驗證都經由此入口測試，不個別測試內部函式
- **歌曲庫服務（`LibraryService`）**：注入記憶體版的 `LibraryStore`，測試新增、移動、刪除、替換影片、無法播放標記的同步、單首匯入比對規則、取代匯入、歌曲庫檔一致性檢查，以及容量不足的處理

另有兩個獨立的純函式直接做單元測試：

- 目前行的時間計算（含時間差與範圍限制）
- YouTube 網址解析
